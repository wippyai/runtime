# Conditional naming snapshot contract

Status: KV primitive and naming-authority conditional capture implemented and
race-tested. Naming wire and client cache are not wired; current native refresh still sends full snapshots.

## Authority check

ConditionalSnapshotReader.ScanAtIndexSince compares known with one immutable
published snapshot. known=0 always scans. Matching nonzero revision returns
unchanged=true without visiting entries. RaftEngine always performs the same
leader barrier as ScanAtIndex first; a cached/follower/local equality is not an
authority check. Failed barrier returns no revision and no unchanged result.
Standalone Service supplies the same operation over its own authoritative view.
The revision covers all KV, so unrelated writes conservatively trigger a scan.

## Required wire/cache binding

Revision alone is insufficient across authority replacement or fresh/diskless
store startup: a different state can reuse the same numeric revision. The wire
needs an authority-lifetime token generated by the serving endpoint, echoed with
the cached revision. Receiver recreation rotates it; switching authority therefore
requires a full response. No W2 edits or mixed-protocol compatibility machinery.
The response must remain bound to authenticated peer, request correlation and
participant incarnation, as existing replies are.

The authority must perform exact-incarnation enrollment/retirement validation
before considering unchanged. A retired participant must never get cache reuse
merely because its last full snapshot was valid. Matching lifetime+revision does
not bypass the Raft barrier. A token/revision mismatch produces a full bounded
snapshot; a future revision cannot be echoed as an unchanged result.

Client caches at most one complete, validated, bounded snapshot. Partial visitor
consumption and canceled/failed validation cannot install a new cache. Mutable
visitor-visible slices must never alias retained cache storage. A purported
unchanged reply without matching locally retained lifetime/revision is invalid.
Discard stale/out-of-order correlations as before.

Unchanged authority state also does not imply local reconciliation has no work:
terminal obligations, timers and observations may have advanced since the last
capture. Preserve generation-aware exclusion cleanup; don't simply skip the
whole refresh because a revision matched. Avoiding re-decoding validated entries
is a separate ownership/immutability improvement from omitting wire payloads.

## Gates before native performance claim

- Matching revision with failed barrier cannot confirm cache.
- Actual mutation during/after comparison cannot produce a torn scan.
- Authority restart/replacement with same numeric revision forces full response.
- Enrollment/retirement/replacement cannot be bypassed by an old cache.
- Unknown cache token, invalid revision, partial decode, late reply, cancellation
  and mutable visitor cannot poison retained snapshot state.
- Repeat native 30s/1000-claim measurement and fault phases against baseline in
  NATIVE-SNAPSHOT-LOAD.md, reporting allocations, traffic and retained state.

## Authority implementation checkpoint

participantAuthority now generates a crypto-random lifetime token per instance.
snapshotForPackageSince performs normal immediate-peer validation, bounded
admission, follower redirect and exact-incarnation enrollment before considering
known revision. Unknown/empty lifetime resets known to zero (full response).
captureSnapshotSince invokes ConditionalSnapshotReader when available and known
is nonzero. An unchanged result must match that exact nonzero revision and must
not have visited any entries. Old full-snapshot callers still request known=0.

Tests prove no entry visits for unchanged, changed data returns full state, a
fresh authority instance with the same store/revision forces a full result,
retired/replaced identities fail before cache reuse, and inconsistent conditional
source results fail. Snapshot.Lifetime/Unchanged are internal only so far; the
existing wire encoder still sends full entries and the client has no cache.

## Wire checkpoint

Candidate v1 request now requires v,c,i,g,r (g=authority lifetime, r=known
revision). Empty g with zero r requests full state; half-specified cache identity
is invalid. Response requires v,c,r,e,i,g,u, with nonempty g and u encoded as
integer 0/1. u=1 requires an empty entries array. Failure/redirect envelopes are
unchanged. This is one candidate protocol, not a compatibility fallback.

Receiver now dispatches lifetime/revision to snapshotForPackageSince and carries
its result fields. Current client still requests full state and rejects any
unchanged response without a retained snapshot. Client cache installation and
reuse remain pending. Bounds/malformed-envelope tests were updated to retain
coverage of entry cardinality and value errors under the new envelope shape.

## Client cache checkpoint

Client now retains one decoded snapshot and its authenticated peer. Only a
complete visit of a naming-valid snapshot for this incarnation may install it;
partial/canceled visits do not install a new cache. Candidate cache validation is
bounded by client maxEntries/maxBytes; callers retain their stricter validation
on each capture. Every visitor receives cloned value bytes, including on the
first full response. No caller can mutate retained cache storage.

Each request sends the cached lifetime/revision only to the matching peer.
Unchanged replies must match both exactly; same-lifetime revision regression is
rejected. Every reuse still awaits a correlated authenticated authority response.
Authority changes force full response. Stop clears retained data after joining
an active request. Tests cover partial/canceled reads, mutations of full/replayed
values, mismatched lifetime/revision, authority recreation and retirement.
